02. 화면 영역별 명세

01 / 키워드 입력

단일 키워드 입력 → 조회 버튼 또는 Enter → 결과 확인. 앞뒤 공백만 제거하고 원문을 유지합니다. 빈 입력은 요청하지 않고 입력란 가까이에 안내합니다.

실서비스 버튼명: ‘검색량 조회’. 요청 중 중복 조회를 막고, 결과가 오면 응답의 키워드를 표시합니다.

02 / 디바이스별 결과

PC·모바일을 먼저, 합계를 보조 카드로 보여줍니다. 단위는 ‘회’, 정수는 천 단위 쉼표로 표기합니다. 디바이스 구분은 모바일에서도 유지합니다.

PC와 모바일 수치는 검색 횟수이며, 중복을 제거한 사용자 수가 아닙니다.

03 / 출처와 조회 정보

네이버 검색광고 키워드도구, 응답 키워드, 조회 시각(KST)을 결과에 붙입니다. 제공 기준을 확인하기 전에는 ‘지난달’ 또는 특정 날짜 범위로 이름 붙이지 않습니다.

04 / 상태와 복구

조회 전에는 입력 안내, 로딩 중에는 진행 상태, 빈 결과에는 키워드 수정 안내, 실패 시에는 재시도 안내를 표시합니다. 이전 키워드의 수치를 새 결과처럼 남겨두지 않습니다.

03. 데이터 표시 기준

기존 대화에서 확인된 필드를 기준으로 한 설계입니다. 실제 연결 시 공식 응답 계약과 집계 기준을 재확인합니다.

화면 항목연결할 데이터표시·계산 규칙
응답 키워드relKeyword입력한 단어와 일치하는 응답인지 확인. 일치 항목이 없으면 관련 키워드를 대신 표시하지 않음.
PC 월간 검색량monthlyPcQcCnt정확한 숫자이면 쉼표 형식으로 표시. ‘< 10’ 등 범위 표기는 그대로 보존.
모바일 월간 검색량monthlyMobileQcCntPC와 같은 규칙. 누락 값은 ‘제공 없음’으로 표시하며 0으로 바꾸지 않음.
전체 월간 검색량PC + 모바일두 값 모두 정확한 숫자일 때만 합산. 범위 값·누락이 섞이면 ‘정확한 합계 제공 불가’ 표시.
조회 시각서비스가 기록한 조회 완료 시각KST로 표시. 데이터의 집계 시작일·종료일과 구분.

후속 검토 범위

성별·연령·월별 추이, 연관키워드 비교, 입찰가 및 예상 성과는 이번 설계에 포함하지 않습니다. 데이터랩 상대 지수를 절대 검색량으로 표시하지 않습니다.

구현 완료 판정

  • 키워드와 PC·모바일 필드가 원본 응답과 일치한다.
  • 범위 값·누락·0을 서로 구분하고 부정확한 합계를 만들지 않는다.
  • 빈 입력, Enter 조회, 중복 요청 방지, 오류 후 재시도를 확인한다.
  • 새 조회 중 이전 결과가 현재 결과로 보이지 않는다.
  • 모바일 한 열 배치, 키보드 탐색, 상태 알림을 확인한다.
  • 인증정보가 HTML·JavaScript·로그에 노출되지 않는다.

  • API 집계 기간 및 갱신 기준 확인.
