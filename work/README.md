# Selected Work

고객사 레퍼런스 페이지입니다. 루트 `index.html`의 `03 — Selected Work` 섹션은 여기서 상위 3건만 보여주고 전체 목록은 이 페이지로 넘깁니다. 두 화면이 같은 `cases.js`를 읽으므로 데이터를 한 곳에서만 고치면 됩니다.

## 데이터 원천

Notion **퍼포먼스마케팅팀 / 고객사 레퍼런스 DB**가 원천입니다. `cases.js`의 필드는 그 DB 스키마와 1:1로 맞춰 두었으니 임의로 필드를 늘리지 않습니다.

| cases.js | Notion 속성 |
| --- | --- |
| (내보내지 않음) | 고객사명 — 내부 식별용. 공개 파일에 넣지 않는다 |
| `displayName` | 표기명 — 사이트에 나가는 유일한 이름 |
| `industry` | 업종 |
| `services` | 서비스 |
| `periodStart` / `periodEnd` | 기간 |
| `summary` | 한줄 요약 |
| `metric` | 성과 지표 |
| `image` | 대표 이미지 |
| `order` | 정렬 순서 |

**Notion → `cases.js` 자동 동기화는 아직 없습니다.** 지금은 이 파일을 직접 편집합니다. 나중에 GitHub Actions가 Notion API로 읽어 이 파일을 생성하게 되며, 토큰은 저장소가 아니라 GitHub Secrets에 둡니다. 브라우저에서 Notion API를 직접 호출하지 않습니다 — 공개 저장소에 토큰을 둘 수 없고, 정적 파일이어야 검색엔진이 읽고 Notion이 느려도 사이트가 멀쩡합니다.

## 케이스를 추가할 때

1. Notion DB에서 **`공개 승인`이 체크된 행**만 대상입니다. 체크는 고객사 동의를 받은 뒤에 합니다.
2. `metric`은 **승인받은 문구를 그대로** 적습니다. 승인본이 없으면 빈 문자열로 둡니다 — 화면에서 성과 영역이 통째로 사라지고, 숫자를 지어내지 않습니다.
3. `displayName`이 사이트에 나가는 유일한 이름입니다. 계약상 실명을 밝힐 수 없으면 여기에 익명 표현(예: `스포츠 용품 자사몰`)을 적습니다. **Notion의 `고객사명`은 이 파일로 내보내지 않습니다** — 이 파일은 공개 URL로 그대로 서빙되므로, 화면에 안 그리는 값이라도 적으면 소스를 여는 누구나 읽을 수 있습니다.
4. `order`는 작을수록 앞입니다. 비우면 맨 뒤로 갑니다.

## 화면 동작

- 케이스가 0건이면 두 화면 모두 안내 문구를 대신 보여줍니다.
- `metric`, `summary`, `periodStart`가 비면 해당 영역이 렌더되지 않습니다. 빈 칸이 남지 않습니다.
- 940px 이하에서 카드 그리드는 1열로 스택됩니다.
