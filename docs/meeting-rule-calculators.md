# 회의 불문율 계산기 — 계산식 정의서 (초안)

상태: **초안 — 사용자 확정 대기** (2026-10-12 작성). 확정 전에는 구현하지 않는다.

## 0. 목적과 원칙

마케팅·MD·콘텐츠 담당자가 모이는 회의에서는 같은 종류의 판단이 반복된다("AOV가 오르면 허용 CAC가 늘어난다",
"몇 주 안에 몇 % 소진해야 리오더가 안 꼬인다" 등). 이 문서는 그 판단을 **계산식(항등식)** 과 **불문율(사람이 정하는
기준값)** 으로 나눠 정의하고, 하나의 계산기 페이지로 만들기 위한 기준을 확정한다.

출처: 2026-10-12 사용자가 제공한 FW 아우터 런칭 회의록 1건. **회의록 원문과 그 안의 실제 숫자(원가율·마진율·물량
등)는 이 공개 저장소에 싣지 않는다.** 이 문서의 숫자는 모두 가상 예시다.

원칙 (기존 `ecommerce-unit-economics`와 같다):

1. **입력이 같으면 결과가 항상 같은 계산만 쓴다.** 소비자 행동을 가정하는 값(세트 구매 비율, 잠식률, 재구매)은
   계산에 넣지 않는다. 필요하면 사용자가 직접 넣는 입력으로만 두고 "가정"이라고 표시한다.
2. **불문율 숫자는 기본값을 지어내지 않는다.** 목표 ROAS, 소진 목표, 재고 기준일, 검정 기준 등은
   `*-config.js`의 기준값으로 분리하고 화면에 "기준값(변경 가능)"으로 표시한다.
3. **금액은 모두 부가세 포함으로 본다** (2026-10-08 결정과 동일). 반품·취소는 0%로 가정하고 결과 옆에 적는다.
4. **허용 CAC는 첫 구매 기준이다.** 재구매·LTV는 반영하지 않는다.
5. 입력은 브라우저 밖으로 나가지 않는다(`localStorage`·URL 파라미터·네트워크 전송 없음).

## 1. 공통 입력과 용어

| 기호 | 이름 | 정의 |
| --- | --- | --- |
| P | 판매가(결제금액) | 고객이 실제 결제하는 금액 |
| C | 상품 원가 | 상품 1개 매입·제조 단가 |
| f | 결제 수수료율 | PG·카드·플랫폼 수수료율 (결제금액 대비) |
| S | 주문당 택배·포장비 | 주문 1건(1박스) 기준 |
| T | 주문당 목표 이익 | 광고비까지 쓰고 주문 1건에 남기고 싶은 금액 (**불문율**) |
| CM | 광고 전 공헌이익 | `P − C − P·f − S` |
| m | 광고 전 공헌이익률 | `CM ÷ P` |
| CPM | 1,000회 노출당 광고비 | 광고 관리자 값 |
| CTR | 클릭률 | 클릭 ÷ 노출 |
| CVR | 구매 전환율 | 구매 ÷ 클릭 (**클릭 기준**으로 고정. 플랫폼 기본값과 다를 수 있어 화면에 기준을 적는다) |

**"마진율"은 단독으로 쓰지 않는다.** 회의에서 "원가율 ○%, 마진율 ○%"처럼 함께 말할 때 마진율은 사람마다
`1 − 원가율`(매출총이익률)일 수도, 수수료·택배비까지 뺀 `m`일 수도 있다. 계산기는 두 값을 각각 이름 붙여
보여준다(패턴 3).

## 2. 패턴별 계산식

### 패턴 1. 허용 CAC — "AOV가 오르면 허용 CAC 범위가 늘어난다"

```
허용 CAC = CM − T
```

- `허용 CAC ≤ 0` 이면 "이 조건에서는 광고비를 쓸 여유가 없다"로 표시하고 음수를 내보내지 않는다.
- 기존 `ecommerce-unit-economics/calculator.js`의 `maxCpa`와 같은 식이다. 새 계산기는 그 파일을 고치지 않고,
  같은 입력에서 같은 값이 나오는지 테스트로 교차 확인한다.

### 패턴 2. 목표 ROAS ↔ CAC — "목표 ROAS ○%"

```
본전 ROAS            = P ÷ CM          (= 1 ÷ m)
목표 ROAS 기준 CAC    = P ÷ 목표 ROAS
목표 ROAS 달성 시 이익 = CM − P ÷ 목표 ROAS
```

- 허용 CAC(패턴 1)와 목표 ROAS 기준 CAC를 나란히 보여주고 **더 작은 쪽이 실제 상한**임을 표시한다.
- 목표 ROAS < 본전 ROAS 이면 "목표를 달성해도 주문마다 손해"로 경고한다.
- ROAS = 결제금액 ÷ 광고비. 광고 관리자 ROAS는 플랫폼마다 매출 집계 기준이 달라 "먼저 확인하세요"로 안내한다.

### 패턴 3. 원가율 → 공헌이익률 분해 — "원가율 ○%로 맞췄고 마진율 ○% 방어 가능"

판매가를 100으로 놓고 순서대로 뺀다.

```
100 − 원가율(C÷P) − 수수료율(f) − 택배비율(S÷P) = 공헌이익률 m
```

- 매출총이익률 `1 − C÷P` 와 `m` 을 함께 보여주고, 둘 사이 차이가 어떤 비용으로 빠졌는지 막대로 보여준다.
- 사용자가 "말한 마진율"을 넣으면 두 값 중 어느 쪽과 같은지, 둘 다 아니면 차이가 얼마인지 표시한다(판정 없이 차이만).

### 패턴 4. 세트(교차 판매) 할인 — "A 구매 시 B ○% 할인으로 AOV를 높인다"

입력: 주력 상품 A(`P_A`, `C_A`), 추가 상품 B(`P_B`, `C_B`), B 할인율 `d`, 세트 추가 포장비 `S_add`(같은 박스면 0).

```
세트 결제금액          = P_A + P_B·(1 − d)
세트 CM               = 세트 결제금액·(1 − f) − C_A − C_B − S − S_add
B를 더해서 늘어난 CM    ΔCM = P_B·(1 − d)·(1 − f) − C_B − S_add
이익이 늘어나는 최대 할인율 d_max = 1 − (C_B + S_add) ÷ (P_B·(1 − f))
세트 허용 CAC          = 세트 CM − T
```

- **"AOV가 오르면 허용 CAC가 늘어난다"는 `ΔCM > 0`일 때만 참이다.** `d ≥ d_max`이면 AOV는 올라도 허용 CAC는
  줄어든다. 화면은 이 조건을 문장으로 보여준다.
- 단품과 세트를 **주문 1건 기준으로 나란히** 비교만 한다. 세트 구매 비율, B를 정가에 샀을 고객의 잠식은
  행동 가정이라 계산하지 않고, 결과 옆에 "반영하지 않음"을 적는다.

### 패턴 5. 퍼널 CAC와 원인 단계 — "CVR이 주춤했다, 매체 세팅만으로는 한계"

```
CAC = CPM ÷ (1,000 × CTR × CVR)
```

- 지난 기간 값(`CPM₀, CTR₀, CVR₀`)을 넣으면 CAC 변화를 세 요인으로 **정확히** 나눈다(로그 분해, 합이 100%):

```
ln(CAC₁ ÷ CAC₀) = ln(CPM₁ ÷ CPM₀) + ln(CTR₀ ÷ CTR₁) + ln(CVR₀ ÷ CVR₁)
```

  기여가 가장 큰 단계를 **하나만** "원인 단계"로 이름 붙인다. 표 전체를 늘어놓지 않는다.
- 허용 CAC에 맞추려면 필요한 CVR = `CPM ÷ (1,000 × CTR × 허용 CAC)` (CTR도 같은 방식).

### 패턴 6. CAC 하향 목표 → 필요한 개선폭 — "신규 CAC 지난 시즌 대비 ○% 하향"

목표 하향률 `r`. 나머지 값이 그대로라는 전제(화면에 명시)에서:

```
CVR만 올린다면  필요 배수 = 1 ÷ (1 − r)     예) r = 15% → CVR 17.6% 상승
CTR만 올린다면  필요 배수 = 1 ÷ (1 − r)
CPM만 낮춘다면  필요 배수 = (1 − r)
CTR × CVR 합쳐서 필요 배수 = 1 ÷ (1 − r)
```

- 랜딩 이탈률 `b`를 넣으면: `CVR = (1 − b) × 이탈하지 않은 방문의 구매율`. 이탈률을 `b₀ → b₁`로 낮출 때
  CVR 배수 = `(1 − b₁) ÷ (1 − b₀)` (이탈하지 않은 방문의 구매율이 그대로라는 전제).
- 개선 효과의 **크기를 예측하지 않는다.** "이만큼 올려야 한다"만 계산한다.

### 패턴 7. 초판 소진 플랜과 리오더 시점 — "○주 차까지 ○% 이상 소진해야 리오더가 안 꼬인다"

입력: 입고 수량 `Q`, 목표 소진율 `s`, 기간 `D`일, 주문당 수량 `u`(세트에 주력 1개면 1), 기간 중 광고 외 예상 주문 `O`
(기본 0 — "전부 광고로 만든다고 가정"으로 표시), 적용 CAC(현재 CAC 또는 허용 CAC 선택).

```
목표 판매 수량   = Q × s
필요 주문 수     = Q × s ÷ u
하루 목표 주문   = 필요 주문 수 ÷ D
광고로 만들 주문 = 필요 주문 수 − O
필요 광고비      = 광고로 만들 주문 × CAC
필요 클릭        = 광고로 만들 주문 ÷ CVR
필요 노출        = 필요 클릭 ÷ CTR        (검산: 필요 노출 × CPM ÷ 1,000 = 필요 광고비)
```

리오더 시점 (리드타임 `L`일, 안전재고 `SS`):

```
재고가 바닥나는 날  = 현재 재고 ÷ 하루 판매량
리오더 발주 마감일  = 바닥나는 날 − L   (안전재고가 있으면 (현재 재고 − SS) ÷ 하루 판매량 − L)
```

- 목표 소진율·기간·안전재고는 **불문율**이다.

### 패턴 8. 옵션별 재고 편중 — "니트 재고가 특정 컬러에 몰려 있으니 그 컬러를 메인 노출"

옵션(컬러·사이즈) `k`마다 재고 `I_k`, 최근 하루 평균 판매 `v_k`:

```
재고 소진 일수   = I_k ÷ v_k            (v_k = 0 이면 "판매 없음"으로 따로 표시)
재고 비중 − 판매 비중 = I_k ÷ ΣI − v_k ÷ Σv
```

- 소진 일수가 긴 순서로 정렬해 "노출 우선 후보"로 보여준다. 몇 일부터 악성 재고로 볼지는 **불문율**.

### 패턴 9. 소재 A/B 테스트 표본·기간 — "훅 3가지 버전으로 쪼개서 테스트"

비교 지표(CTR, 3초 재생률 = 3초 재생 ÷ 노출, CVR 중 선택)의 현재 값 `p₁`, 확인하고 싶은 개선폭으로 `p₂`:

```
버전당 필요 표본 n = (z₁₋α/2 · √(2p̄(1 − p̄)) + z₁₋β · √(p₁(1 − p₁) + p₂(1 − p₂)))² ÷ (p₂ − p₁)²
  p̄ = (p₁ + p₂) ÷ 2
버전이 k개면 비교 횟수만큼 α를 나눈다(α ÷ (k − 1), 기준안 1개 대비)
필요 기간(일)   = n × k ÷ 하루 노출(또는 클릭)
```

- 유의수준 α와 검정력 1 − β는 **불문율**이다. 화면 본문에는 통계 용어를 쓰지 않고 "버전당 필요 노출 수·필요 일수"만 보여준다.
- 광고 플랫폼이 성과 좋은 소재에 노출을 몰아주면 무작위 분할이 아니다. 플랫폼의 A/B 테스트 기능으로 나눠야
  이 계산이 맞는다는 주의를 적는다.

## 5. 구현 계획 (확정 후)

- 슬러그 제안: `meeting-rule-calculator/` (이름 제안: "회의 불문율 계산기"). `data/tools.json`에 `public: false`로
  시작하고, 화면 검수 뒤 공개 여부를 정한다.
- 입력 한 벌(공통 입력)을 공유하고 패턴별 결과 카드를 쌓는 구조. 새 회의록에서 패턴이 나오면 카드만 추가한다.
- 파일 구조는 기존 견적 도구와 같다: `rule-config.js`(가상 예시·기준값·문구) + `calculator.js`(공식) +
  `index.html` + `scripts/test_meeting_rule_calculator.js`(4절 값 고정, 패턴 1과 기존 `maxCpa` 교차 확인,
  패턴 5 로그 분해 합 = 100%, 패턴 4 `d = d_max`에서 ΔCM = 0, 외부 전송 경로 0건).
- 기존 `ecommerce-unit-economics`는 수정하지 않는다.

## 6. 확정이 필요한 것

1. 9개 패턴을 1차에 모두 넣을지, 1~6(손익·광고)만 먼저 넣고 7~9(재고·테스트)는 2차로 미룰지.
2. 불문율 기준값을 화면 기본값으로 채울지 비워둘지: 주문당 목표 이익, 목표 ROAS, CAC 하향률, 소진율·기간,
   안전재고, 악성 재고 기준일, A/B 테스트 α·검정력.
3. CVR을 클릭 기준으로 고정하는 것(패턴 5·6·7·9 공통).
4. 슬러그·페이지 이름.
